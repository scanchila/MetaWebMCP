Compatibility for the existing web

Give any website a useful WebMCP surface.

MetaWebMCP observes the parts of a site an agent can safely use, turns them into bounded semantic recipes, and exposes those recipes as simple tools—without waiting for the site to ship native WebMCP.

How it works

Compatibility, one workflow at a time.

A website does not need complete native coverage to become useful to an agent. MetaWebMCP finds the safe, observable portion and gives it a stable semantic shape.

  1. 01
    Observe the real interface

    Use an owned page, supplied HTML, or an accessibility snapshot from the calling agent’s existing browser session.

  2. 02
    Shape a bounded recipe

    Turn accessible controls into a small tool with a clear name, schema, evidence, risk, and deterministic browser steps.

  3. 03
    Activate, verify, and reuse

    Add the recipe to the live tool registry, let the agent invoke it by intent, and verify the visible result before export.

One contract · two destinations

Use the recipe now. Integrate it when you own the site.

A
Agent-side compatibility

Operate the website as it exists.

The calling agent keeps its current page and authenticated session. A generated WebMCP tool gives it a validated recipe with the accessible targets, inputs, and expected result needed to complete the workflow.

  • No change to the target site
  • No unrestricted JavaScript
  • Reusable semantic invocation
B
Native site integration

Take the same recipe into your own site.

Export a standalone repository with the reviewed ToolSpecs and direct document.modelContext.registerTool(...) calls. Integrate them as-is, or bind the contracts to your application functions and permission checks.

  • Direct imperative WebMCP
  • Owned, editable source
  • Evidence and eval guidance included

Compatible to the degree the interface allows

Broad reach without pretending every action is safe.

MetaWebMCP omits ambiguous or inaccessible controls, keeps consequential actions behind review and confirmation, and never weakens the access already enforced by the target website.
